# M0.4 — Target semantics and label-quality audit

## Status

**Descriptive only. Neither primary target is frozen by this audit.**

## Official definitions being checked

The official KuaiRand documentation states:

- `is_click` is UI-dependent: in a two-column UI it means a click; in a single-column UI it means a `valid_play` label derived from play time and duration.
- `long_view` equals 1 when `play_time_ms >= duration_ms` for videos at most 18 seconds long, or when `play_time_ms >= 18,000` for videos longer than 18 seconds.
- `play_time_ms` is user view time in milliseconds.
- `duration_ms` is video duration in milliseconds.

Because the public documentation does not map each numeric `tab` value to a UI type, RankLab must not reconstruct `is_click` mechanically from play/duration without additional authoritative evidence.

## Checks

For each of the three logs the audit reports:

- overall `is_click` and `long_view` prevalence;
- `P(long_view | click)` and `P(click | long_view)`;
- target prevalence by duration bucket;
- target prevalence by `tab` code;
- nonpositive-duration, negative-play, and play-greater-than-duration counts;
- agreement between the provided `long_view` label and the official duration/play-time rule for rows with positive observed duration.

The duration buckets are descriptive only and are not promoted to primary cohorts.

## Interpretation gate

M0.4 can reject or retain candidate targets based on semantics and quality, but it must not choose a target because it creates a more dramatic standard-vs-randomized difference.
