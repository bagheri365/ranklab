# M0.2 — Logging-Regime and Target Descriptive Audit

## Purpose

M0.2 inspects the three KuaiRand-Pure interaction logs before RankLab freezes target semantics, ranking units, or matched-support rules.

The audit is descriptive. It does **not** establish that randomized exposure is ground truth, that the two regimes are comparable, or that `is_click` / `long_view` are valid primary targets.

## Generated artifact

```text
runs/m0/regime_audit.json
```

Generate it with:

```bash
make audit-regimes
```

## Required descriptive checks

For each log:

- row count
- observed date range
- unique users
- unique videos
- `is_rand` distribution
- `tab` distribution
- `is_click` value counts and prevalence
- `long_view` value counts and prevalence
- missingness for audit columns
- duration/play-time sanity counts

For the two Apr 22–May 8 evaluation logs:

- shared users
- shared videos
- user Jaccard overlap
- video Jaccard overlap
- coverage of each regime by the shared support

## Interpretation gate

M0.2 may identify candidate restrictions or semantic concerns, but none become primary-study rules until they are reviewed and frozen later in M0.
