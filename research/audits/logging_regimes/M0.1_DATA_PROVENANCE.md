- Upstream repository/documentation: https://github.com/chongminggao/KuaiRand

The official documentation describes random intervention as replacing a small fraction of recommended videos with a video sampled from a candidate pool. RankLab will preserve the neutral terms **standard-policy exposure** and **randomized exposure** and will not treat randomized exposure as privileged ground truth.

## Upstream log semantics to verify locally

The official documentation states that:

- `log_random_4_22_to_5_08_pure.csv` contains interactions resulting from random intervention.
- `log_standard_4_22_to_5_08_pure.csv` contains standard-recommendation interactions from the same calendar period.
- `log_standard_4_08_to_4_21_pure.csv` contains standard-recommendation history from the preceding two weeks for the same users.
- log rows include `is_click`, `long_view`, `is_rand`, and `tab` fields.

These statements are **source documentation**, not yet RankLab's frozen interpretation. M0 must inspect the downloaded files and verify scenario, target, and ranking-unit semantics before M1.

## Local integrity record

After download/extraction, run:

```bash
ranklab audit-data --data-dir data/raw/KuaiRand-Pure/data
```

The command emits SHA-256 hashes for every expected CSV and validates required log headers. Preserve that output in an M0 run artifact; do not commit raw data.
