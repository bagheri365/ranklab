This milestone measures whether the frozen BPR/LightGCN training index universe
covers the entities appearing in the already-frozen evaluation supports.

It also reconciles stale scaffold fields in the protocol registry with the
actual frozen primary fitting policy.

## 1. Why this audit is required

BPR and LightGCN can score only users/items represented in their indexed
training state unless an explicit unseen-entity policy is introduced.

Popularity can assign zero to unseen items and ignores user identity, so using
a different implicit rule for the latent-factor/graph models would make the
three-model comparison inconsistent.

Before choosing an unseen-entity rule, RankLab therefore measures how common
unseen users and unseen items actually are.

## 2. Training index universe

The audit reconstructs the exact model index universe from the already-frozen
pairwise training contract:

- pairwise-eligible training users;
- items appearing in eligible positive or eligible logged-negative pairs.

This is the same population used by all BPR and LightGCN primary checkpoints.

No model checkpoint needs to be loaded.

Expected training index counts from prior M0 work are:

- users: 23,638;
- items: 7,527.

## 3. Evaluation supports audited

Coverage is measured separately for standard and randomized evaluation under:

1. primary shared users + shared videos;
2. shared-tab sensitivity;
3. tab=1 descriptive sensitivity.

Candidate pairs are structurally collapsed exactly as in the M0.16 audit.

## 4. Quantities reported

For every regime/support combination:

- rows;
- unique candidate pairs;
- users;
- items;
- seen users;
- unseen users;
- seen items;
- unseen items;
- candidate pairs with both user and item seen;
- pairs with unseen user;
- pairs with unseen item;
- pairs with any unseen entity;
- seen-user fraction;
- seen-item fraction;
- fully scorable pair fraction.

## 5. Guardrail

This audit does not:

- load a checkpoint;
- score a candidate;
- rank a candidate;
- compute NDCG;
- compare models.

The output can therefore inform unseen-entity semantics without exposing model
performance.

## 6. Protocol-registry reconciliation

The original scaffold registry still contained:

- seeds `365,366,367`;
- `cross_seed_aggregation: mean`;
- wording implying per-seed validation checkpoint selection.

Those fields no longer describe the frozen implementation.

M0.17 updates the registry to the already-documented facts:

- primary seeds are `0,1,2,3,4`;
- tuning seed is `0`;
- BPR fixed primary endpoint is 1 epoch;
- LightGCN fixed primary endpoint is 28 epochs;
- no per-seed validation re-selection occurs;
- cross-seed aggregation remains unfrozen until the evaluation/statistical
  protocol is finalized.

This is a registry correction, not a new model-selection decision.
