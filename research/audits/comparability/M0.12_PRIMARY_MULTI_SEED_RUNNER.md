# M0.12 — Primary Multi-Seed Fitting Runner

## Status

**Shared primary seed policy: FROZEN**

**Primary-fit implementation: READY FOR ENGINEERING VALIDATION**

**Primary checkpoints: NOT YET FIT**

**Overall M0 protocol: UNFROZEN**

M0.12 implements the M0.11 primary fitting policy.

The critical implementation requirement is that primary fitting must not quietly re-use validation for checkpoint selection.

---

## 1. Training-only data access

The primary-fit runner reads only labels from the frozen Apr 9–16 training dates.

Rows outside those dates are skipped before user ID, item ID, or `is_click` are parsed.

Therefore the runner does not compute or inspect:

- Apr 17–21 validation relevance;
- Apr 22–May 8 standard-policy evaluation relevance;
- randomized-policy evaluation relevance.

This is stricter than merely computing validation and choosing not to use it.

---

## 2. Pair construction

The runner reproduces the frozen training-pair contract:

- pair collapse by any-click;
- positive pairs are any-click training pairs;
- negatives are exposed pairs with no click anywhere in training;
- users require at least one positive and one eligible negative;
- LightGCN graph edges use only pairwise-eligible positive pairs.

Expected full-data training counts remain:

- training rows: 1,011,214;
- unique pairs: 967,832;
- positive pairs: 463,260;
- negative pairs: 504,572;
- pairwise-eligible users: 23,638;
- excluded positive users: 1,206;
- eligible positive pairs: 458,854;
- eligible negative pairs: 500,836;
- indexed items: 7,527.

These counts must be checked before accepting the primary fit.

---

## 3. BPR final fitting

For seeds `0,1,2,3,4`, BPR uses:

- embedding dimension 32;
- learning rate 0.05;
- regularization `1e-3`;
- batch size 4096;
- initialization std 0.01;
- exactly 1 epoch.

The endpoint after epoch 1 is saved directly.

No validation metric is computed.

---

## 4. LightGCN final fitting

For seeds `0,1,2,3,4`, LightGCN uses:

- embedding dimension 32;
- propagation depth 2;
- learning rate 2.0;
- regularization `1e-4`;
- gradient chunk size 8192;
- initialization std 0.01;
- exactly 28 epochs.

The endpoint after epoch 28 is saved directly.

No validation metric is computed.

---

## 5. Primary checkpoint manifests

Each model manifest records:

- data SHA256;
- protocol SHA256;
- frozen training dates;
- frozen seed policy;
- training-population counts;
- per-seed hyperparameters;
- fixed epoch count;
- epoch-level training loss;
- checkpoint filename;
- checkpoint SHA256;
- explicit `validation_used_for_primary_fit = false`.

---

## 6. Seed-1 reproducibility

After original seed sets are fit, the runner can repeat seed 1 in:

`runs/m0/primary_multiseed/repro/<model>/`

The repeated file never overwrites the original checkpoint.

The runner compares SHA256 values and fails if they differ.

Both BPR seed 1 and LightGCN seed 1 must pass this check before M1.

---

## 7. Expected tuning-seed consistency

Because seed 0 uses the same frozen hyperparameters and fixed selected epoch as the tuning winner:

- primary BPR seed 0 is expected to reproduce the selected BPR tuning checkpoint;
- primary LightGCN seed 0 is expected to reproduce the selected LightGCN tuning checkpoint.

These hashes should be physically compared after primary fitting.

This is an integrity check, not a new selection rule.

---

## 8. What M0.12 does not decide

M0.12 does not freeze:

- seed aggregation;
- confidence intervals;
- paired statistical tests;
- final evaluation support;
- evaluation under randomized exposure;
- M1 execution.

It only implements already-frozen primary fitting.
