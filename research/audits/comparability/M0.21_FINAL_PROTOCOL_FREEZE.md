## 1. Dataset identity

KuaiRand-Pure is treated as an upstream unversioned archive because the audited
source does not provide a release version identifier that RankLab can safely
promote to a semantic version.

RankLab therefore records the exact six audited CSV hashes and derives a
canonical dataset-manifest digest from lines of the form:

`<filename><space><sha256><newline>`

sorted lexicographically by filename.

Canonical manifest digest:

`292d78feaff8af210fe5225c2db669fc279de616debcc3c10898e5f3833e10b2`

The authoritative per-file hashes remain in:

`research/audits/logging_regimes/M0.1_DATA_PROVENANCE.md`

The aggregate digest is an internal RankLab dataset identity, not an upstream
KuaiRand release checksum.

## 7. Canonical protocol hash

The canonical M0 protocol hash is SHA-256 over the exact bytes of:

`research/protocol_frozen_m0.yaml`

after all M0.21 registry fields are finalized.

The digest is stored separately in:

`research/protocol_frozen_m0.sha256`

to avoid a self-referential hash field inside the YAML.

The identical digest is copied into the M1 primary config.

A unit test recomputes the hash and checks both references, so any later
protocol drift fails the test until deliberately re-frozen.
